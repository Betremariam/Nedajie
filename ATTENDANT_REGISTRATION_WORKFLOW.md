# Attendant Registration Workflow

## Overview
The attendant registration process has been simplified to a three-step workflow involving the Station Owner, Approver Admin, and the Attendant.

## New Workflow

### Step 1: Station Owner Registers Attendant
**Location:** Admin Panel > Owner Dashboard > Attendant Management

The station owner registers a new attendant with minimal information:
- **Full Name** - Legal name of the attendant
- **Phone Number** - Contact number (used for login)
- **Employment Proof** - Document upload (ID, contract, etc.)

**What happens:**
- Attendant record is created with `isApproved: false` and `isEnabled: false`
- No password is set at this stage (password field is empty)
- Station details (stationName, city, region) are automatically populated from the owner's profile
- Attendant is linked to the station owner via `ownerId`

### Step 2: Approver Admin Reviews and Approves
**Location:** Admin Panel > Approver Dashboard > Approve Attendants

The approver admin reviews pending attendant registrations:
- Views attendant details and employment proof document
- Can approve or reject the registration
- Approval sets `isApproved: true`

**What happens:**
- Approved attendants become visible to their station owner
- Rejected attendants are deleted from the system
- QR code is generated for the approved attendant

### Step 3: Station Owner Generates Password
**Location:** Admin Panel > Owner Dashboard > Attendant Management

After approval, the station owner can:
- View all their attendants with approval status
- Generate a password for approved attendants by clicking "Generate Password"
- View and share the generated password with the attendant

**What happens:**
- A random secure password is generated (16 characters)
- Password is hashed and stored in the database
- `isEnabled` is set to `true` (attendant can now login)
- Password is displayed once to the owner (must be shared with attendant)

### Step 4: Attendant Logs In
**Location:** Mobile App > Login Screen

The attendant can now login using:
- **Phone Number** - Provided during registration
- **Password** - Generated by the station owner

**Important Notes:**
- The "Register Now" option has been removed from the mobile app
- Attendants cannot self-register
- A message informs users that registration must be done by station owners

## API Endpoints

### Station Owner Endpoints
```
POST   /api/owners/attendant                    - Register new attendant
GET    /api/owners/my-attendants                - Get all attendants
POST   /api/owners/attendant/:id/generate-password - Generate password for approved attendant
PATCH  /api/owners/attendant/:id/toggle         - Enable/disable attendant
```

### Approver Admin Endpoints
```
GET    /api/admins/unapproved-attendants        - Get pending attendants
PUT    /api/admins/approve-attendant/:id        - Approve attendant
DELETE /api/admins/reject-attendant/:id         - Reject and delete attendant
```

### Attendant Endpoints
```
POST   /api/attendants/login                    - Login with phone and password
```

## Database Schema Changes

The `FuelAttendant` model includes:
- `password` - Can be empty string initially, set after approval
- `isApproved` - Set by approver admin
- `isEnabled` - Set to true when password is generated
- `ownerId` - Links attendant to station owner
- `stationName`, `city`, `region` - Auto-populated from owner

## Security Considerations

1. **Password Generation**: Passwords are randomly generated (16 chars) and immediately hashed
2. **Access Control**: Only the owning station can generate passwords for their attendants
3. **Approval Required**: Attendants cannot login until approved by admin
4. **Password Required**: Even after approval, login requires password to be generated first
5. **Owner Control**: Station owners can enable/disable attendants at any time

## User Experience Improvements

1. **Simplified Registration**: Only 3 fields required (name, phone, document)
2. **Clear Workflow**: Each role has specific responsibilities
3. **Security**: Passwords are generated securely, not chosen by users
4. **Accountability**: All attendants are linked to their station owner
5. **Mobile App**: Clear message that registration is done by station owners
